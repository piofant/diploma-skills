# Грабли сборки ВКР

Семь проблем, каждая из которых стоила вечера. Все воспроизводились на реальной работе (86 страниц, 13 таблиц, 18 рисунков, 9 приложений).

---

## 1. Google Docs красит заголовки синим

**Симптом.** Локально в Word всё чёрное. Импортируешь `.docx` в Google Docs — все заголовки синие.

**Причина.** Google Docs игнорирует style-level цвет именованных стилей и подставляет свою тему.

**Лечение.** Прямое (run-level) форматирование переживает импорт. На каждый `<w:r>` внутри заголовка:

```xml
<w:rPr>
  <w:color w:val="000000"/>
</w:rPr>
```

Плюс вычистить `themeColor`, `themeTint`, `themeShade` — иначе Google перекрасит обратно.

→ `fix_headings_black.py`

---

## 2. Google Docs схлопывает таблицы pandoc

**Симптом.** Таблица с пятью колонками превращается в колонки шириной в один символ. Текст переносится по букве.

**Причина.** Pandoc генерит borderless-таблицы с `tblLayout=autofit` и без явных ширин. Google Docs пересчитывает autofit по-своему.

**Лечение.** Проставить `<w:tblLayout w:type="fixed"/>`, явные `<w:tblW>` и `<w:gridCol w:w="...">` на всю ширину страницы, плюс видимые границы.

→ `fix_tables.py`

**Отдельно:** скрипт должен быть **внутри build-пайплайна**, а не лежать рядом. Фикс, который запускается руками, — это отложенная регрессия: следующая пересборка всё сломает обратно.

## 3. Word-поле `{TOC}` не вычисляется → пустое Содержание

**Симптом.** В Word оглавление есть. В Google Docs — заголовок «СОДЕРЖАНИЕ» и пустота под ним.

**Причина.** Google Docs не вычисляет Word field codes при импорте. Поле остаётся невычисленным.

**Лечение.** Собрать **статическое** оглавление — обычные абзацы с текстом и номерами. Номера взять из outline отрендеренного PDF:

```python
from pypdf import PdfReader
r = PdfReader(pdf_path)
page = r.get_destination_page_number(outline_item) + 1
```

Плюс right-tab с `w:leader="dot"` для точечной линии.

→ `gen_static_toc.py`

---

## 4. Номера в статическом TOC съезжают на 1–2 страницы

**Симптом.** Сгенерировал статический TOC — номера не совпадают с реальными страницами. Стабильно на 1–2 меньше.

**Причина.** Замкнутый круг: номера берутся из PDF, где TOC был **полем-заглушкой** в одну строку. Статический TOC занимает 2–3 страницы, вся пагинация уезжает.

**Лечение.** Convergence-pass. После вставки статического TOC — перерендерить PDF, ещё раз прочитать outline, обновить номера в уже вставленном TOC:

```
render → gen_toc → render → gen_toc (update mode) → render
```

Скрипт должен уметь **два режима**: вставить TOC вместо поля (первый проход) и обновить уже вставленный (последующие).

→ `gen_static_toc.py`, функция `_is_static_toc_entry()`

**Плюс `page_offset`:** если в документе `<w:pgNumType w:start="2"/>`, физический индекс страницы из `pypdf` не равен номеру в footer. Нужна поправка.

## 5. UNO-подход к LibreOffice крашит `LibreOfficePython` на macOS

**Симптом.** При каждой конвертации выскакивает системный диалог о падении `LibreOfficePython`. Файл при этом собирается.

**Причина.** Классический рецепт «поднять `soffice --accept=socket` и подключиться через UNO из Python» на macOS падает. Скрипт молча уходит в fallback, но диалог остаётся.

**Лечение.** Не использовать UNO. Обычный headless-конверт работает стабильно:

```bash
soffice --headless --convert-to pdf --outdir "$DIR" file.docx
```

TOC-поле LibreOffice при этом всё равно раскрывает, outline строит — то есть UNO не нужен.

→ `update_and_convert.py`

## 6. H4 остаётся полужирным вопреки стилю

**Симптом.** В `make_reference.py` для `Heading 4` явно `bold=False`. В PDF заголовки третьего уровня всё равно жирные, местами ещё и курсивные.

**Причина.** Pandoc навешивает **прямое** символьное форматирование на runs заголовков. Оно перебивает стиль.

**Лечение.** Хард-сет в пост-процессоре:

```xml
<w:b w:val="0"/>
<w:bCs w:val="0"/>
<w:i w:val="0"/>
<w:iCs w:val="0"/>
```

Именно `w:val="0"`, а не удаление тега — удаление возвращает наследование от стиля, которое тоже может быть перебито.

→ `fix_headings_black.py`, функция `_strip_bold_italic_run()`

---

## 7. Вузовская система приклеивает свой титульный лист

**Симптом.** Работу вернули на доработку: в загруженном PDF два титульных листа.

**Причина.** Личный кабинет вуза формирует титул/задание/аннотацию из данных формы и приклеивает к загруженному файлу.

**Лечение.** Сборка без собственного титула:
- отдельный `merge_no_title.py` (не склеивает `titlepage.docx`)
- `<w:pgNumType w:start="2"/>` — нумерация начинается с 2, потому что стр. 1 займёт титул системы
- `page_offset=1` в генераторе TOC, чтобы номера в оглавлении совпали с footer

**Уточните до сдачи**, приклеивает ли ваша система титул. Это экономит цикл «загрузил → отклонили → пересобрал».

→ `merge_no_title.py`, `add_page_numbers_no_title.py`

---

## Общий принцип

Проверяйте на **той поверхности, где работу читают**. Если комиссия смотрит PDF — проверяйте PDF. Если работа живёт в Google Docs — проверяйте Google-рендер, а не локальный Word.

И рендерьте страницы в картинки, чтобы посмотреть глазами:

```bash
pdftoppm -png -r 90 diploma.pdf /tmp/check/p
```

Текстовая проверка (`pdftotext | grep`) ловит содержание, но не ловит «съехало», «наложилось», «не тот шрифт».
